# 扫描转录与固定 v2 票档容量对账设计（`ranked-ballots-link`）

本文说明新增的独立对账链路：把一份**扫描转录清单**与一份**固定 v2 电子票档**做
组合一致性核对，判断全部扫描记录能否同时由该票档容纳，并给出每条记录在所有
合法完整分配中可归属的票组集合。它**不修改**票档、归档库或抽核活动，**不产出**
计票胜者或统计认证，也不能证明扫描来源真实或票档本身正确。

## 1. 范围与边界

- 只读两个输入：一个 v2 报告 JSON（最多 32 MB）和一个扫描转录 JSON（最多 8 MB）。
- 输出一个普通 JSON 结果文件，原子替换、符号链接目的地拒绝、输入与输出路径必须
  不同；任何格式或核验失败退出 2 且保留旧输出字节。合法但无法完整分配时**成功**
  输出 `infeasible` 与可独立核验的 Hall 见证。
- 候选 1..100、票组至多 20000、weight 为 1..10^9 整数，允许空票档与 `winner=null`。
  本链路**不**套用抽核的 12 候选、非空胜者限定。
- 扫描记录至多 5000，派生相容边至多 200000；超过边数上限即退出 2。工作数据规模只
  取决于票组数、扫描数与相容边数，**绝不**按 weight 展开个体票，也**不**枚举完整
  分配。

## 2. 输入契约

### 2.1 v2 报告

顶层恰为 `schema_version=2`、`revision`（0..2^63-1 整数）、`candidates`、
`ballots`、`snapshot_sha256`、`result`。候选与票组按 id 升序，票组项恰为
`{id, ranking, weight}`，ranking 无重复或未知候选。校验包括：

1. 报告输入字节必须等于 `archive.canonical_bytes(report)`（规范 JSON：UTF-8、
   `ensure_ascii=False`、`sort_keys`、无空白、末尾一个换行），任何美化或损坏字节
   一律拒绝；
2. `snapshot_sha256` 必须等于规范 `{candidates, ballots}` 字节的 SHA256；
3. `result` 必须逐字节语义等于对该票档调用 v1 `analyze` 的输出。

同 ranking 的不同票组 id 仍是**不同组**，不按 ranking 合并；weight 是该组可分配
张数上限，未使用容量允许保留。

### 2.2 扫描转录

顶层恰为 `{"records":[{"id","slots"},...]}`，`records` 允许为空。每条记录是一张
已扫描票：

- `slots` 的长度就是完整 ranking 长度（0..100）；候选 id 是已读位置，`null` 是该
  位置无法辨读。`null` 不是未填写候选，也不使 ranking 长度伸缩；空数组只与空
  ranking 相容。
- 已读候选不得重复、必须属于 `report.candidates`；扫描 id 沿用 `common.ident`
  规则且不可重复。记录顺序不构成优先权，结果按 scan_id 升序展示。

## 3. 相容关系

扫描 `slots` 与票组 `ranking` 相容，当且仅当长度相同且每个非 `null` 位置的候选
相等。相容关系完全由输入导出，不因某次分配成功就停止搜集可能身份。

派生按 ranking 长度分组，并只对扫描实际约束的位置建倒排索引：先取候选集合最小的
约束位置做基准集合，再与其余约束位置的候选集合求交。工作量随扫描数、票组数与最终
边数增长；派生过程中边数累计超过 200000 立即失败，不构造后续网络、不写输出。

## 4. 全局容量模型与算法

把问题建成二分 b-匹配流网络：

```
source --1--> 每个扫描节点 --1--> 相容票组节点 --weight--> sink
```

每条扫描必须送出恰好 1 个单位，票组流入不得超过其 weight，未用容量自然允许。

1. **一次 Dinic 最大流**判断可行性：最大流等于扫描数即可覆盖全部记录。网络深度
   至多为 3，增广递归深度有固定上界，不随输入规模增长。
2. **一次残量图 SCC（迭代 Tarjan，无输入规模递归）分类全部相容边**。对扫描→票组
   的单位边 `(u, v)`：
   - 若该边已带流（饱和），它已经出现在当前某个最大流里，故 `v` 是 `u` 的可能
     归属；
   - 若未带流，残量弧 `u→v` 存在；当且仅当 `u`、`v` 在残量图同一强连通分量时，
     存在一条 `v` 回到 `u` 的残量交替路，与该边合成一个把 1 个单位改派到 `v` 的
     另一最大流。不同 SCC 则该边在任何完整分配中都不可用。

因此每条扫描的可能票组集合由**一次**最大流加**一次** SCC 全部得出，不为每条边
重新独立求完整分配，也不枚举任何完整分配。仅一个可能 id 为 `forced`，多个为
`ambiguous`；局部相容集合或单次求解的任意选择都不会被当作答案。未用容量产生的
替代与封闭交替环产生的替代都由同一 SCC 判据覆盖（见验收例：只剩 `s1` 时两组皆
可能）。

## 5. 不可行见证（Hall 缺口）

最大流小于扫描数时，从 source 沿残量正向弧可达的节点构成集合 `R`。令
`S = R 中的扫描`、`N(S) = R 中的票组`，则由流网络结构 `N(S)` 恰为 `S` 的全部
相容邻接组，且每个邻接组到 sink 的容量边都饱和。最小割容量给出

```
|S| > Σ_{g ∈ N(S)} weight(g)
```

见证输出 `scan_ids`、`ballot_ids`（均升序去重，后者恰为邻接组全集）、
`record_count = |S|`、`capacity_sum` 与正缺口 `deficit = record_count -
capacity_sum`。任何核验者仅凭输入即可重建邻接关系并复核缺口，无需重跑本实现。

## 6. 输出契约

顶层至少含 `schema_version=1`、`report_sha256`（报告**输入字节** SHA256）、
`scans_sha256`（扫描输入字节 SHA256）、`snapshot_sha256`（报告内固定值）、
`status`（`feasible`/`infeasible`）。

- `feasible`：`assignment` 每项 `{scan_id, ballot_id}`，每条扫描恰一次且逐记录
  相容、不超容量；`records` 按 scan_id 升序，每项
  `{scan_id, possible_ballot_ids, classification}`，可能 id 升序、去重、非空；
  `witness` 为 `null`。
- `infeasible`：`assignment` 为 `null`、`records` 为空，`witness` 含上述五个
  字段且 `deficit > 0`。

见证与完整分配可任选正确的一份，但同输入重复运行字节一致（排序键固定、无时间戳或
环境字段，落盘经 `common.save` 规范序列化后原子替换）。

## 7. 严格输入与失败语义

严格 JSON：拒绝重复键、非有限值、浮点、布尔冒充整数、未知字段、重复扫描 id、重复
已知候选或未知候选，以及超长 slots/records、超界 revision/weight。任一失败在写输出
之前抛出，CLI 映射为退出码 2 并在 stderr 给出原因，旧输出文件保持不变。

## 8. 为何不能替代纸票随机抽核

- 本链路只核对**输入事实的组合一致性**：给定转录与给定票档，容量上是否相容、哪些
  归属被全局约束强制。它不接触物理纸票，不验证扫描是否真来自对应纸票，也不验证电子
  票档是否忠实于选票本身。
- 抽核（`ranked-ballots-audit`）是带随机种子、断言与 e 过程的统计活动，回答“电子
  结果是否被人工纸票证据支持”；本链路没有随机抽样、没有断言、没有风险水平，也不
  产生任何认证结论。
- `forced` 只相对于**给定相容信息与容量约束**成立：更多辨读位置或不同票档会改变
  相容边，从而改变可能集合。它不是对纸票真实归属的鉴定。
