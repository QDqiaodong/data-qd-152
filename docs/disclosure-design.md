# 首选票公开汇总表的遮盖规划（`ranked-ballots-disclosure`）

本链路只读一份离线首选票汇总输入，规划“必须遮盖格 + 至多十个允许额外遮盖格”
中要额外遮盖哪些格，并发布**只含公开汇总表、行列合计与遮盖位置**的正式报告。
它不修改 v1 计票、归档、纸票抽核、扫描对账、两两偏好或候选退出敏感性分析，
也不产出赢家或统计认证。

## 输入契约

顶层恰为 `{precincts, protect, optional}`。

- `precincts`：1..8 项 `{id,candidates,ballots}`，选区 ID 唯一。每区是一份独立
  的 v1 票组输入（`id`、`ranking`、`weight` 1..10^9 的整数），由既有
  `pairwise.validate` 校验，因此与 `analyze` 的票组规则一致。各区候选集合相同，
  含 1..5 个候选；所有选区合计至多 20000 个票组。票组 ID 只在本区内唯一，
  不同选区可以复用同一 ID。**禁止**按 `weight` 展开票组。
- `protect`：非空必遮坐标数组；`optional`：可选坐标数组，最多 10 项。每项为
  `{precinct,candidate}`；`candidate:null` 是空白列，不与任何候选 ID 混用。
  坐标必须存在，两个数组分别不得重复且互不相交。
- 沿用严格 JSON 解析：重复键、非有限数值、未知字段与超过 8 MB 的输入一律拒绝。

首选票汇总：非空 `ranking` 的全部 `weight` 计入首位候选，空 `ranking` 的全部
`weight` 计入独立的空白列。公开表每选区一行，候选 ID 升序的列之后是空白列。

## 保护语义

固定一个遮盖方案后，公开信息是：未遮盖格的值、每行合计、每列合计。每个被遮盖格
可以取任意非负整数，只要存在一张与全部公开格和边际合计相容的非负整数表。

一个必遮格被该方案保护，当且仅当它在相容表中**能取到至少两个不同的值**。
不同必遮格可以由不同的相容表分别证明。输入票组内容与每组权重不是公开约束；
替代表只需满足公开格与边际合计。

每个方案都从头判断：按该方案留下的可见格重新检验所有必遮格，不沿用上一方案的
推断结果。选出额外遮盖最少的方案；同样少时取排序后坐标序列字典序最小者。
坐标先按选区 ID、后按候选 ID 排序，空白列排在所有候选之后。

判定不逐一枚举可能的格值。以真实表（必然可行，因为它给出了公开格与合计）为基准，
只有被遮盖格带有剩余弧：正向可增（行、列合计保持），且当真实值 `v>0` 时可减。
必遮格可变当且仅当剩余网络中存在经过它的环——即从“列结点”可达“行结点”
（可增）或反向可达且 `v>0`（可减）。因此 10^9 权重与 1 权重的代价完全相同。

**这是单份发布表的可推断性指标**：它不保证抵御外部信息、历史发布，也不保证抵御
对遮盖选择过程本身的推断。

## 无解与失败

若没有任何允许的额外遮盖能让所有必遮格都可变——例如某行合计为零，其全部格即使
都可遮盖也仍被迫为零——退出 2，stderr 说明原因，且不泄露任何格值。输入错误、
写入错误同样退出 2。输入/输出同路径和输出符号链接拒绝；失败保留旧输出字节，
成功以单次原子替换更新输出。

## 报告字段

`schema_version:1`、`columns`、`column_totals`、`rows`、`suppressed`：

- `columns`：候选 ID 升序，末尾为 `null`（空白列）。
- `column_totals`：与列对齐的整数数组，含空白列合计。
- `rows`：按选区 ID 排序，每项 `{precinct,total,values}`；`values` 与列对齐，
  遮盖处为 `null`，未遮盖格（含零值）为整数。
- `suppressed`：按坐标顺序列出全部遮盖格，格式同输入坐标，不区分必遮与附加遮盖。

报告以 UTF-8 输出，不含内部可行表、隐藏格原值或源文件摘要。重排等价输入的
选区、候选、票组及两类坐标数组，公开报告字节不变。

## 算法与独立核对

1. 校验并归一化：选区按 ID、候选按 ID、票组按 ID 排序；计算首选矩阵与边际。
2. 对至多 1024 个 `optional` 子集（按大小、再按坐标字典序枚举）逐一判断：
   构建仅含遮盖格的剩余图，对每个必遮格做一次（跳过该格自身弧的）可达性判断。
3. 第一个成功者即最少且字典序最小的方案。

测试对小整数表用独立穷举核对：枚举全部相容非负整数表、收集每个必遮格的可取值、
按同样的“最少 + 字典序”规则挑选方案，和生产结果逐格比较；生产路径另有测试证明
评估次数只随 `optional` 子集数增长，不随格值大小增长。
